# Difficulties

Problems we hit, what we tried, and what we did. Each terminal appends only under its own heading.

## Terminal 1 — backend / pipeline

- **Gemini key rejected (401 UNAUTHENTICATED, ACCESS_TOKEN_TYPE_UNSUPPORTED)** — 2026-10-23. `GEMINI_API_KEY` in `.env` starts with `AQ.` (53 chars); AI Studio API keys start with `AIza`, so this looks like an OAuth-style token. Fix: create a key at aistudio.google.com/apikey. Until then real-mode rewrite falls to the deterministic minimal rung; MOCK=1 covers UI work.
- **No python3.11 / ffmpeg on the machine** — used a 3.13 venv (all deps install fine) and `brew install ffmpeg`.

### Round 3 (2026-10-24)
- **Gemini key has no credits (402 RESOURCE_EXHAUSTED "prepayment credits are depleted").** The old code saw `RESOURCE_EXHAUSTED`, treated it as a rate limit and retried on the 31b model, wasting budget. Now 402/401/403 raise `GemmaUnavailable` with no retry: the 402 rewrite step takes 156–447 ms (5 real runs) before the deterministic rung.
- **Health could not tell "no credits" without spending money.** Gemini's free `models.get` and `count_tokens` both return OK on the no-credit key (checked live). So `/api/health` reports the error of the most recent real call (`gemma`/`decisions`: `no_credits`, `auth_error`), saved in `cache/provider_status.json` so a restart still knows. Before any real call, `gemma:"ok"` only means "key accepted".
- **Without Gemma, self-corrections were spoken as-is or blocked.** The real demo clip transcribes with no punctuation and compound values ("on uh Friday at five PM no wait sorry Monday at five PM an- and everyone…"), so a simple "X marker Y" rule never fired and every job ended at `rung=original`. The deterministic rung now resolves (a) inline same-kind corrections, including compound "day at time" values, and (b) sentence restarts with ≥60 % content-word overlap. It is conservative: different kinds, a partial restatement ("Friday at 5 PM, sorry, Monday") and "Friday actually, Monday is booked" are left alone. 42 tests (11 false-positive cases).
- **Guard gaps found while testing (T2's guard.py, reported, not changed):** "let me rephrase" and a bare "no" ("5, no, 6") are not correction markers, so the guard keeps the old value as final or counts "no" as a negation; "We meet Monday. Actually, Tuesday works too" fails the guard even unchanged (Monday marked superseded). In all three cases the ladder falls back to the original, so nothing wrong is spoken.
- **Live transcription is slow on long clips.** Every tick re-transcribes the whole recording. With word timestamps the medians were 1.6 / 2.5 / 3.9 / 6.9 s for 5 / 10 / 20 / 40 s of audio. Live passes don't need word timestamps; without them: 1.25 / 1.48 / 1.88 / 4.05 s. Client interval: 3 s with one request in flight.
- **Port 8000 was taken by a uvicorn started outside this terminal** (pid 5356, 10:14). Not killed; the Round 3 real runs used port 8010.
- **Real numbers (8010, real ASR/Twinly, Gemma 402, Decisions 429):** cold start to `asr_loaded` 4–5 s (weights cached). `make smoke` 5/5 three times; final run wall 3.5 / 2.5 / 2.0 / 2.5 / 2.5 s (ASR 1.6–2.4 s, `rung=minimal`, guard PASS, Friday → Monday resolved). `SPEAK=1`: one chunk, 4.0 s of audio in 5.2 s, served `audio/mp4` (21 305 bytes).

## Terminal 2 — ASR / guard / eval

- **Twinly G1: `voice_not_set_up`, no audio yet** — 2026-10-23. `GET /v1/me` is 200 in ~1.8 s and shows `mac.online:true` (app 4.2), but `mac.setup.voice` is a how-to string ("Record a voice: Twinly, Voice, then Build my clone") instead of `true`. The one real `POST /v1/voice/speak?wait=25` ("Hello, this is a test.") returned in 2.8 s with HTTP **200** and a job body `status:"failed"`, `error.code:"voice_not_set_up"` (not a 4xx), so errors can arrive inside a 200 job. Fix needs the Mac owner: Twinly app > Voice > Build my clone. Not retried (no credit burned on a known failure). Audio playback and real latency are still unverified until the clone exists. Shapes saved in `fixtures/real_twinly_me.json`, `fixtures/real_twinly_speak.json`; `voice.health()` reads `me.mac.setup.voice === true` as `voice_ready`.

- **Decisions G2: OpenAI key has zero credits (`429 credit_balance_exhausted`)** — 2026-10-23. `POST /v1/decisions` with `gpt-6-luna` returns `429 insufficient_quota` "You have no credits remaining", so no successful response was captured and the answer shape (`answers[].probability` / `choice`) is still the docs' guess. What we did verify with free validation errors (no billing): `GET /v1/models` lists `gpt-6-luna` for this key (so no model gating); `/v1/decisions` exists (a bogus path is 404, ours is 400 on bad bodies); question `type` is one of `predicate | choice | score`; predicate needs `instructions`; choice needs `choices` as objects (`value`, `description`); score needs `levels`; **max 400 questions per call** (11 accepted, 401 rejected), which settles the 10-vs-400 conflict in docs/md/05. Fix needs a human: add credits at platform.openai.com/settings/organization/billing, then re-run `python -m backend.decide "..."` once and save the response to `fixtures/real_decisions_*.json`. Until then `decide.analyze` returns `available=False` with the reason (verified live), and the guard runs deterministic-only with verifier `offline`. Raw error in `fixtures/real_decisions_429_no_credits.json`.
- **Guard design choice: contract says `check()` is async and returns pydantic `GuardResult`** — the pure rules live in sync `check_rules()` (42 tests, no network) and `check()` wraps them, so tests stay instant.

### Round 2 (2026-10-24)

- **Twinly G1 still blocked: `voice_starting`, ~43 s per failed attempt** — 00:40. `GET /v1/me` now shows `mac.setup.voice: true`, but `/me` cannot see whether the voice *engine* is running. Real run through `TwinlyClient` (2 POSTs, hard-capped by a test transport): `POST /voice/speak?wait=25` -> **202** after 26.5 s (`status:"running"`), then `GET /jobs/{id}?wait=25` -> 200 after 18 s with `status:"failed"`, `error.code:"voice_starting"` ("voice engine is still starting on this Mac. Try again in a minute"). The re-post failed the same way. Whole job ~43 s from create to fail. Raw exchanges in `fixtures/real_twinly_voice_starting.json`. **User action:** quit Twinly fully (Cmd-Q), reopen, wait ~1 min, then run `python -m backend.voice "Hello, this is a test."` once. Spend log shows 9 lines counted (it counts every accepted job, failed ones included, so it over-counts and stays on the safe side).
- **The voice_starting retry loop could not fit `main.py`'s 60 s cap** — with 43 s per failed attempt, "retry 3 times after 5 s" means ~3 minutes, so `/api/speak` would have died with a misleading "took too long". Fix: `render()` only re-posts if another attempt of the same length still fits in a 55 s budget; otherwise it raises at once with "Quit and reopen the Twinly app". Test built from the real capture.
- **Decisions G2 still blocked: `429 credit_balance_exhausted`** — 00:41. Same error as round 1, 0.4 s. `/api/health` said `decisions: ok` because it only checks that a key exists. Added `decide.health()` (one 1-predicate call, cached 60 s), which correctly returns `("error", "429 credit_balance_exhausted")`. **T1:** use it in `_decisions_status()`. The success response shape is still unverified, so `decide.py` still parses the shape from docs/md/05.
- **Hard deadlines** — `decide.analyze` 15 s and `decide.verify` 10 s for the whole pass, retries included; `guard.check` caps the verifier at 11 s. Any timeout or error becomes `available=False` / `verifier:"offline"`, never an exception. Tested with a transport that hangs for 5 s (returns in <1 s with deadlines patched to 0.2 s).
- **Guard false-positive/false-negative measurement** — `eval/guard_cases.json`: 61 hand-written, Gemma-style rewrites (30 good, 31 bad) over the eval utterances plus 15 new originals (the user's CS-major sentence, ASR-misheard name, room numbers, budget, professor, launch, spoken times...), plus identity rewrites of the eval utterances. Run `python eval/guard_eval.py`.
  - Before the fixes (first 59 cases + 8 identity rewrites): **4/37 false positives, 5/30 false negatives.**
  - After (61 cases + 6 identity rewrites, n=67): **0/36 false positives, 3/31 false negatives.**
  - Fixes: (1) protected terms accept a close ASR mishearing in the verbatim ("Ariane" ~ "Aryan", similarity >= 0.7, same first letter), so a rewrite that fixes the name passes *only when the user listed it*; (2) a negation repeated in a false start ("can't, uh, we cannot") counts once; (3) a negation moved onto a value the speaker affirmed ("not Thursday" -> "not Friday") fails; (4) a capitalised sentence-start word is a name candidate when the system dictionary (`/usr/share/dict/words`) has no lower-case entry for it (catches "Sarah" -> "Priya"; "Attendance", "Please" are not names). Without a word list this check is skipped.
  - Two identity rewrites (canonical, number self-correction) were excluded from the "good" set: they still say "Friday"/"ten", and docs/md/08 bans the superseded value even verbatim.
  - **Remaining false negatives (all the user's sentence):** major/minor swapped, "and finance" added, minor dropped. No number, date, name, negation, hedge or quantifier signal changes, so the deterministic layer can't see them. They need the Decisions verifier (`added_new_information`, `meaning_preserved`), which is offline until there are credits. Mitigation that works today: listing "computer science" and "business administration" as protected terms catches the dropped minor (`cs_dropped_protected`).
- **T1: `main.py` does not pass protected terms or mode into `guard.check`** — the name-alias fix only works if `guard.check(verbatim, rewrite, mode=..., protected=job.protected_terms)` is called that way.
- **Gemma in the eval** — the first real canonical run took 45 s and ended with `ServerError 500 INTERNAL`, so the ladder fell to `original`. Full numbers in `eval/RESULTS.md`.

## Terminal 3 — frontend / docs

- **Browser recording vs. playback gestures** — 2026-10-23. Chained `<audio>` playback after an async speak request can be blocked by autoplay rules. Fix: one shared `<audio>` element is primed with a silent clip inside the Approve click, then its `src` is swapped per chunk.
- **Playback state overwrote recording state** — a chunk finishing after the user pressed Record set the UI back to "playing". Fix: cancel chained playback (generation counter) at the start of `startRecording`, before the microphone opens. Found with a headless-Chrome run and a fake microphone.
- **`display:flex` beat the `hidden` attribute** — the empty error box and override checkbox were visible on a clean page. Fix: `[hidden] { display: none !important }`. Found from a screenshot, not from tests.
- **Backend edit reasons are codes** (`restructure`, `self_correction`), not sentences — mapped to plain English in the UI rather than changing the contract.
- **No real demo clip** — `fixtures/backup_demo.m4a` is a placeholder tone, which real ASR would reject as no speech. The "Use demo clip" button uses `frontend/demo-clip.m4a`, generated with macOS `say` reading the canonical announcement (a synthetic voice, not a person). Replace it with a real recording of the demo speaker before finals.
- **Twinly offline UX ambiguity** — docs/md/10 says Record is blocked when Twinly is offline, docs/md/11 says text-only mode. We kept Record enabled and switched only speaking off, so the cleaned-up text is still useful.

### Round 2 (2026-10-24)

- **The real UI sat on "4 Edit / Editing…" forever** — Gemma hung and the page trusted the backend to finish. Fix: a client watchdog independent of the backend. It warns after 15 s with no progress or when a stage passes 2x its docs/md/03 budget, shows live elapsed seconds on the active stage, offers "Use text without AI edit" / "Try again", and gives up at 60 s. Subtle part: the SSE stream sends keep-alives and polling returns the same snapshot forever, so only a *change* (new stage event, longer trace, new status) counts as progress. Every `fetch` now has a deadline too (25 s, 120 s for speak). Tested against `frontend/e2e/scenario_server.py`, a fake backend that hangs on purpose.
- **Edit is "slow" on almost every real run** — the docs' rewrite budget is 2–5 s, but Gemma takes ~16 s, so the "taking longer than usual" box appears on most real runs at ~10 s. We kept the budget (the box is informative, not an error), but the message says it normally answers in under 10 s, which is optimistic for Gemma 4 today.
- **Backend watchdog vs. UI hard stop** — T1's job deadline (`JOB_DEADLINE_S`) is 90 s and the UI stops waiting at 60 s, so on a fully stuck backend the UI's way out appears first and the backend's own "original text" fallback is never seen. T1's watchdog also leaves no failed rewrite in the trace, only a note, so the first version of the fallback box blamed the meaning check; it now reads the note.
- **Users didn't understand fallback results** — the rung badge said "Safe fallback: showing the lightest edit". It now explains why, from the trace ("The AI editor (Gemma 4) had an internal error, so we only removed filler words… Nothing was reworded"), and trace rows translate 401/429/500/timeout into short sentences with the raw error in a details toggle.
- **`voice_starting` reaches the browser as code `internal`** — backend/voice.py raises `internal` with "Twinly voice is still starting." The UI matches the message as well as the code, so the user still gets "wait a minute" instead of a generic error.
- **The names field was easy to miss** — "Ariane Patel" for "Aryan Patel". It is now a highlighted field above the mode control, remembered per browser, and a Names check after processing says whether each name was heard, misheard (fuzzy match on the transcript), or kept, with a one-click replace. It only uses fields the backend already returns.
- **Speak errors showed far from the button** — the error box sat above the results, so after pressing Approve nothing visible changed. Speak errors now render directly under the action buttons. Found from a screenshot.
- **An "obvious" test was wrong** — "Use text without AI edit" on the canonical clip leaves "Friday, no wait, Monday" (only the AI resolves self-corrections), so the guard correctly blocks it. The test expected speak to be enabled; the page was right. The fallback box now says self-corrections stay as spoken.
- **Font sizes under 18 px** — round 1 used 15–16 px secondary text. An automated audit in `e2e.py` now checks every visible text element for size >= 18 px and contrast >= 4.5:1 in light and dark themes.
